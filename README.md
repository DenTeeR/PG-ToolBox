# PG-ToolBox

ربات تلگرام برای مدیریت **PasarGuard v5.6.0**، بر پایهٔ Holderbot و فورک Alfred.
این نسخه از APIهای پاسارگارد استفاده می‌کند. مرجع سازگاری:
[نسخهٔ رسمی v5.6.0](https://github.com/PasarGuard/panel/releases/tag/v5.6.0)،
کامیت `2b75db15cb0019a00252c59f9d1c34e6082a121f`.

## امکانات

- ساخت کاربر تکی یا گروهی، با انتخاب گروه‌های پاسارگارد، حجم و زمان اعتبار.
- شروع اعتبار از اولین اتصال؛ زمان صفر، اشتراک فعال با اعتبار نامحدود می‌سازد.
- قالب‌های محلی شامل حجم، روز و شناسهٔ گروه‌ها.
- مشاهدهٔ مصرف، وضعیت، تاریخ انقضا، آخرین اتصال و آخرین برنامهٔ دریافت‌کنندهٔ اشتراک.
- لینک اشتراک، QR، جست‌وجو و حذف کاربر با تأیید.
- گزارش PDF بر اساس وضعیت یا بازهٔ آخرین اتصال / دریافت اشتراک؛ کاربران بدون سابقه هم در گزارش دوم قرار می‌گیرند.
- آمار برنامه‌های کاربران با API تجمیعی تاریخچهٔ اشتراک.
- افزودن و حذف ادمین، تغییر رمز و انتخاب نقش‌های موجود پاسارگارد. نقش Owner از طریق این API قابل تخصیص نیست.
- وضعیت نودها، ضریب مصرف، فعال/غیرفعال کردن، درخواست اتصال مجدد و مانیتورینگ.
- ویرایش اعلان داخلی اشتراک و دریافت هشدار تغییر وضعیت کاربران به expired / limited.

## نصب

یک سرور Debian/Ubuntu با systemd و Python 3.10 تا 3.12، توکن ربات تلگرام، شناسهٔ عددی تلگرام مدیر و آدرس پنل لازم است.
ربات می‌تواند روی سروری جدا از پنل نصب شود. قبل از ساخت کاربر، در پنل پاسارگارد گروه بسازید و اینباندها را به آن نسبت دهید.

```bash
curl -fsSL https://raw.githubusercontent.com/DenTeeR/PG-ToolBox/main/holderbot.sh -o /tmp/pg-toolbox-install.sh
sudo bash /tmp/pg-toolbox-install.sh
```

نصب‌کننده مخزن **DenTeeR/PG-ToolBox** را در `/opt/pg-toolbox` دریافت می‌کند، محیط Python می‌سازد و تنظیمات را می‌پرسد.
احراز هویت با **API key پاسارگارد** یا نام کاربری و رمز ادمین انجام می‌شود. برای API key، دسترسی‌ها و سقف درخواست را متناسب با استفاده تنظیم کنید.

دسترسی‌های لازم بسته به قابلیت استفاده‌شده:

| قابلیت | مجوزهای API |
| --- | --- |
| کاربران، QR و گزارش‌ها | `users.read` |
| ساخت / حذف کاربر | `users.create`, `users.delete`, `groups.read` |
| ادمین‌ها و نقش‌ها | `admins.read/create/update/delete`, `admin_roles.read` |
| نودها | `nodes.read/update/reconnect` |
| اعلان اشتراک | `settings.read/update` |

اصل احراز هویت در مرحلهٔ تنظیمات بررسی می‌شود؛ دسترسی هر قابلیت هنگام استفاده توسط خود پنل کنترل می‌شود.
نام سرویس `pg-toolbox` و کاربر اجرای آن `pg-toolbox` است. بعد از نصب به ربات پیام `/start` بدهید.
مانیتورینگ و هشدار انقضا در شروع خاموش هستند و از منوی ربات فعال می‌شوند.

```bash
sudo systemctl restart pg-toolbox
sudo journalctl -u pg-toolbox -f
sudo systemctl status pg-toolbox
```

برای نصب یک شاخهٔ آزمایشی، همان شاخه را هم در URL نصب‌کننده و هم در `PG_BRANCH` مشخص کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/DenTeeR/PG-ToolBox/feat/pasarguard-v5/holderbot.sh -o /tmp/pg-toolbox-install.sh
sudo PG_BRANCH=feat/pasarguard-v5 bash /tmp/pg-toolbox-install.sh
```

نصب دوباره اطلاعات موجود را پاک نمی‌کند. قبل از بازنویسی تنظیمات، از دیتابیس نسخهٔ پشتیبان با دسترسی محدود ساخته می‌شود.
`restart.sh` سرویس را راه‌اندازی مجدد می‌کند؛ `uninstall.sh` سرویس را حذف می‌کند و فایل‌ها و دیتابیس را نگه می‌دارد.

## مهاجرت از Holderbot

1. از `holder.db` و نصب قبلی نسخهٔ پشتیبان بگیرید و فرآیندها و cron قدیمی Holderbot را متوقف کنید. نصب‌کنندهٔ جدید به آن‌ها دست نمی‌زند.
2. نسخهٔ جدید را در مسیر جدا نصب کنید و تنظیمات پنل **پاسارگارد** را وارد کنید.
3. قالب‌ها را با شناسهٔ گروه‌های پاسارگارد دوباره بسازید. قالب‌های اینباند قدیمی به گروه تبدیل نمی‌شوند.

این ابزار حساب‌های داخل پنل قدیمی را به پنل جدید منتقل نمی‌کند؛ موضوع این مهاجرت، اتصال و عملکرد ربات است.
اگر دیتابیس قدیمی را دستی استفاده کنید، `setup.py` را اجرا کنید. بدون تنظیم مجدد، اتصال به پنل قبلی شروع نمی‌شود.
جدول‌های قدیمی حفظ می‌شوند؛ قالب‌های جدید در `pg_templates` ذخیره می‌شوند.

**Notice:** ترفند تغییر اینباند کاربران منقضی‌شده حذف شده است. اعلان جدید از تنظیم `subscription.announce` خود پاسارگارد استفاده می‌کند و برای **همهٔ اشتراک‌ها** است؛ نمایش آن به پشتیبانی برنامهٔ کاربر، مانند Happ یا v2RayTun، بستگی دارد.
هشدار اتمام زمان/حجم به **مدیر ربات** ارسال می‌شود و حساب یا گروه کاربر را تغییر نمی‌دهد. هنگام فعال‌سازی، وضعیت فعلی مبنا قرار می‌گیرد؛ فقط تغییرات بعدی هشدار می‌دهند.
تاریخچهٔ دریافت اشتراک تابع سیاست نگهداری تاریخچه در پنل است؛ زمان یا برنامه‌ای که پنل نگه نداشته قابل بازیابی نیست.

## اجرای دستی و تنظیمات

```bash
git clone https://github.com/DenTeeR/PG-ToolBox.git
cd PG-ToolBox
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python setup.py
.venv/bin/python holder.py
```

دیتابیس پیش‌فرض `holder.db` کنار کد است و با مجوز `0600` نگهداری می‌شود. اعتبارنامه‌ها و session تلگرام را منتشر نکنید.
فقط شناسهٔ تلگرام ثبت‌شده در تنظیمات به ربات دسترسی دارد. رمز ادمین جدید در state ذخیره نمی‌شود؛ پیام آن بعد از استفاده، در صورت امکان حذف می‌شود.

| متغیر محیطی | کاربرد |
| --- | --- |
| `PG_DB` | مسیر دیتابیس؛ برای اجرای دستی / تست |
| `PG_HTTP_TIMEOUT` | مهلت هر درخواست، پیش‌فرض ۲۰ ثانیه |
| `PG_CA_BUNDLE` | مسیر CA خصوصی؛ تأیید TLS به‌صورت پیش‌فرض روشن است |
| `PG_VERIFY_TLS=false` | فقط برای محیط آزمایشی با گواهی خودامضا |
| `TG_API_ID`, `TG_API_HASH` | جایگزینی مشخصات برنامهٔ تلگرام به‌جامانده از Holderbot |
| `PG_INSTALL_DIR`, `PG_BRANCH`, `PG_REPOSITORY` | تغییر مقصد، شاخه و مخزن نصب‌کننده |
| `PG_PYTHON` | مفسر Python نصب‌کننده، پیش‌فرض `python3`؛ مثلاً `python3.12` |

متغیرهای زمان اجرای سرویس را در `/etc/pg-toolbox.env` قرار دهید و سرویس را restart کنید.
برای استفاده از CA خصوصی در مرحلهٔ نصب نیز `PG_CA_BUNDLE` را به دستور نصب بدهید.
TgCrypto شتاب‌دهندهٔ اختیاری Pyrogram است؛ برای عملکرد اصلی لازم نیست.

## آزمون‌ها

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/ruff check .
bash -n holderbot.sh restart.sh uninstall.sh
```

آزمون‌ها شامل قرارداد مسیرها و مدل‌های استخراج‌شده از سورس رسمی `v5.6.0`، درخواست HTTP واقعی به سرور محلی، احراز هویت، صفحه‌بندی، تاریخ‌ها، مهاجرت دیتابیس و جریان‌های تلگرام با ارتباط شبیه‌سازی‌شده هستند.
هیچ پنل واقعی یا حساب تلگرامی برای اجرای تست‌ها لازم نیست. این آزمون‌ها جای بررسی عملی روی پنل و تلگرام واقعی را نمی‌گیرند.
برای بازسازی snapshot قرارداد از checkout همان نسخه، اسکریپت `scripts/update_api_contract.py` را با Python 3.14 اجرا کنید؛ این نسخهٔ Python مربوط به سورس رسمی پنل است، نه اجرای ربات.
